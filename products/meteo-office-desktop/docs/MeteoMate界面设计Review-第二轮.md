# MeteoMate 界面设计 Review（第二轮）

> 基线：`dc365/goose` 最新 main（`d2c286cb1`，2026-07-31），MeteoMate 0.2.0 Beta 4
> 范围：`products/meteo-office-desktop`（桌面端 + SkillHub 管理后台）
> 角度：审美、界面设计、设计语言一致性。功能正确性不在本轮范围。
> 验证方式：实机运行（Electron + SkillHub 服务）逐屏截图走查，证据见 `screenshots-r2/` 目录（文中编号对应）。

---

## 一、总体印象

上一轮的设计精修层（`styles-polish.css`）已被合入并扩展（670 → 1732 行，补了发布审核等新板块），应用整体观感统一、干净：冷调中性底、深海军蓝主行动色、品牌蓝激活态、柔和分层阴影。新增的**场景卡彩色图标**、**能力中心分段页签**、**完成状态 pill（已完成 1.1s ⌄）**、**发布审核 QC 面板**都符合这套语言，水准在线（截图 01/09/14）。

本轮的核心结论不是"哪里丑"，而是：**设计语言的覆盖半径没有跟上功能扩张的速度**。Beta 2–4 新增了工作流编辑器、成果预览工作台、Computer Use PiP、专家团协作条等一批新界面，它们各自带了独立的样式文件，polish 层对它们**零覆盖**，其中一个（PiP）甚至自建了一整套色板。再叠加样式加载顺序被意外破坏，设计体系开始出现"多套方言"的苗头。以下按优先级展开。

---

## 二、P0：设计语言体系的结构性问题

### P0-1 polish 覆盖层的"最后加载"约定已被破坏

`styles-polish.css` 文件头明确写着"本文件只做增量覆盖，**最后加载**，不改写既有样式表"——它是整个设计语言的仲裁者，依赖加载顺序生效。但当前 `index.html` 中：

```
24: styles-polish.css      ← 覆盖层
25: styles-team.css        ← 却排在它后面
26: styles-preview.css     ← 同上
```

新增的 team / preview 样式表插在了覆盖层**之后**。一旦它们与 polish 写了同一选择器（卡片、面板、徽章这类高重合度命名），polish 的规则就会被静默压掉，表现为"精修莫名失效"，且排查困难。

**建议**：把 `styles-polish.css` 的 `<link>` 移到所有样式表之后（一行改动）；并把"polish 必须最后加载"写进 `index.html` 注释，防止后续新增样式表再次插错位置。

### P0-2 新界面游离在设计语言之外

对 `styles-polish.css` 全量检索：工作流（workflow）、成果预览（preview）、PiP、专家团协作条（team）相关规则数为 **0**。即这四个新界面完全没有继承精修语言，它们的观感完全取决于各自样式文件的自觉程度。其中：

- **工作流编辑器**（`styles-workflows.css`，3574 行）：整体克制、底子不错，但细节（节点卡阴影、端口、连线色）与主应用卡片体系有可见的色温/圆角差异（截图 06）。
- **Computer Use PiP**（`computer-pip.css`）：自建了一整套独立令牌——`--live-mint: #35c879`、`--snapshot-blue: #6c8fd3`、`--waiting-amber`、`--error-coral`、`--ink-primary` 等。命名法（ink/mist/frost）与主应用（polish-navy/polish-accent）完全不同，**mint 绿更与品牌色系无关**。这是目前产品里第二套设计语言的雏形。
- **成果预览工作台**情况最好（有 design-qa.md 佐证其对齐了主应用 token），但仍未进 polish 层的管辖范围。

**建议**：
1. 令牌统一：把 `computer-pip.css` 的色板映射到主应用令牌（live→语义 success，snapshot-blue→`--polish-accent`，ink→polish-text 体系），删除私有命名；
2. 在 `styles-polish.css` 末尾为工作流编辑器、预览工作台、PiP、协作条各开一个 section，把阴影尺度、圆角、徽章、按钮统一到 `--polish-*` 变量——让新界面"自动"继承设计语言，而不是各自重写。

### P0-3 状态色各自为政

当前产品中同时存在多套"状态绿"：

| 位置 | 元素 | 颜色 |
|---|---|---|
| 技能中心（截图 04） | "精选"徽章、"精选推荐"链接 | 绿色系 |
| 工具中心（截图 05） | "已连接"徽章 | 另一绿色系 |
| PiP | live 状态 | mint `#35c879` |
| QC 面板（截图 09） | 阻塞项 / 提醒 | 红 / 琥珀（这套是规范的） |

"精选"本质是**推荐/品牌强调**语义，却用了成功绿；而品牌蓝只出现在激活态。绿色家族三种写法互不相同。

**建议**：定义一组语义色令牌（`--polish-success / warning / error / info / featured`），"精选"归入 `featured`（建议用品牌蓝浅底而非绿），三处绿色收敛到同一个 `success`。这类收敛趁界面还少时做，成本最低。

## 三、P1：具体界面问题

### P1-1 目录页标题栏在窄窗口下溢出（截图 13）

1540px 下标题栏已接近饱和（页签 ×4 + 搜索 + 同步 + 我的专家 + 创建专家 + 窗口控制 ×3）。把视口缩到 **1200px** 实测：

- "工作流"页签被裁切只剩"工"；
- "同步""我的专家""创建专家"全部**竖向换行**，标题栏高度被撑开，观感凌乱。

窗口最小宽度并没有拦到 1540（用户完全可能缩到 1200–1300）。

**建议**：给标题栏定一套响应式降级——搜索框设 `min-width` 并可折叠为图标；"我的专家"收成星标图标按钮；"创建专家"在窄屏只保留 "+"；页签组允许横向滚动。或者把窗口最小宽度钉在 ~1280 并保证该宽度下不溢出。

### P1-2 工作流编辑器（截图 06）

新界面里问题最集中的一个：

1. **初始画布不居中、不自适应**：打开模板后 9 个节点堆在画布左上 1/4 区域，下方大片空白。虽有"适应"按钮，但首屏应该自动 fit + 居中——这是节点编辑器的通行做法。
2. **标题栏信息过载**：一行挤了返回、4 个目录页签、版本号、撤销/重做、设置、导出 YAML、测试运行、发布、窗口控制约 12 个控件。编辑器是沉浸场景，**目录页签（专家/技能/工具/工作流）在这里没有上下文意义**，应隐藏，换成工作流名称（可点击改名）。
3. **"测试运行"出现两次**：标题栏一次、右下角悬浮按钮一次。保留一处（建议留下右下悬浮主按钮，与底部状态条形成"运行区"）。
4. **操作提示太边缘**：右上角的"拖动端口连线 · 右键添加节点 · ⌘/Ctrl+滚轮缩放"是小号灰字，新用户几乎不可能注意到。建议首次进入时用画布内浮层提示，或在空画布态直接写在画布中央。
5. **缺缩略导航**：没有 minimap。节点一多（真实业务流轻松 20+ 节点）就没有方位感。中期补上。

### P1-3 对话正文缺少阅读宽度约束（截图 07/14）

助手消息卡片通栏铺开，正文长行可达 1100px+。气象分析这类长文本在超宽行下阅读效率明显下降（眼动回扫成本高）。Markdown 排版本身（标题、表格、代码、引用）是及格的，但：

- 正文列建议 `max-width: 760–800px`（表格、代码块可放宽到 1000px）；
- 表格表头与数据行视觉区分弱（表头无底色/加粗对比），密集数据表（截图 07 的评分表）建议表头加浅底、斑马纹或行 hover。

### P1-4 设置页内容列偏窄（截图 08）

1540px 宽下，设置内容卡片约 820px 且靠左，右半屏是大面积空白。内容列可以放宽到 960–1040px 或整体居中，宽屏利用率会好很多。

### P1-5 后台 logo 与新品牌图形不一致（截图 11/12）

SkillHub 管理后台的 logo 仍是**纯色方块 + "MM" 文字**（登录页、侧边栏顶、工作台头三处），而 favicon 已是新设计的"双驼峰 M 渐变描边"图形。同理，桌面端助理头像也是字母 "M" 圆形。

**建议**：后台三处 logo 和桌面端头像统一改用 favicon 那张 SVG（已有现成资产，换引用即可），品牌触点立刻一致。

## 五、值得保持的做法

本轮走查中也确认了一批做对的地方，后续迭代别回退：

1. **场景卡彩色图标**（截图 01）：蓝/紫/琥珀/青的彩色图标方块是首页最出彩的元素，色板克制；
2. **完成状态 pill**（截图 14）："已完成 1.1s ⌄"可折叠的状态条，信息密度合适；
3. **发布审核 QC 面板**（截图 09）：左表单右门禁的两栏结构、红/琥珀语义色，是新产品面里设计完成度最高的；
4. **能力中心分段页签 + 目录搜索**（截图 01/04/05）：信息架构清晰；
5. **空状态体系统一**（截图 02/03 等）：浅色圆角方块图标 + 标题 + 说明 + 行动按钮的范式贯穿所有空态；
6. **design-qa.md 流程**：成果预览工作台留了完整的 Design QA 记录（对比目标、密度归一化、视口弹性），这个流程值得推广到每个新界面。
