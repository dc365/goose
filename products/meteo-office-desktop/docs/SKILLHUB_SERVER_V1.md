# MeteoMate SkillHub Server V1

## 1. 目标

SkillHub Server V1 把本地 Capability Center 扩展为可自托管的团队能力注册中心：

```text
Skill Creator / 本地 ZIP
        ↓
上传草稿版本
        ↓
安全检查与内容寻址存储
        ↓
发布与 Ed25519 签名
        ↓
精选、搜索、推荐与套件
        ↓
MeteoMate Desktop 下载、验签、再次本地检查
        ↓
用户确认安装
```

SkillHub 不修改 Goose Core。Goose 继续从标准 `.agents/skills/` 目录发现已经安装的 Skill。

## 2. 服务目录

```text
services/skillhub/
├── cmd/skillhub/
├── internal/
│   ├── api/
│   ├── auth/
│   ├── skillpkg/
│   ├── store/
│   └── trust/
├── Dockerfile
├── docker-compose.yml
├── openapi.yaml
└── README.md
```

当前元数据使用原子 JSON 文件，包使用 SHA-256 内容寻址存储。该版本适合内部试用和小团队；后续可以通过 Store 接口迁移至 PostgreSQL 与 MinIO。

## 3. 生命周期

```text
Upload
  → Draft
  → Pending review（按组织策略或高风险触发）
  → Published + Signed
  → Deprecated
```

已发布版本不可覆盖。内容发生变化必须创建新版本。

### 发布风险规则

- 严重风险包拒绝上传；
- 高风险包由发布者提交后进入管理员审核；
- 中低风险包按组织策略直接发布，或进入管理员审核；
- 管理员可批准发布，也可填写原因退回草稿；
- 下载后桌面端仍会执行本地 Capability Center 检查。

## 4. 身份与可见范围

单位内网用户由管理员在 `/admin/` 后台创建，并通过用户名和密码登录。首个管理员使用一次性环境变量引导创建，服务 Token 仅保留给自动化或运维集成：

```text
viewer
publisher
admin
```

Skill 可见范围：

```text
public
organization
private
```

登录会话只保存在服务端内存中。停用用户、修改或重置密码、管理员撤销会话以及服务重启都会使会话失效。

## 5. 包签名

服务首次启动时生成 Ed25519 密钥：

```text
data/trust/ed25519.json
```

签名消息：

```text
<skill-id>\n<version>\n<package-sha256>
```

桌面端下载后会：

1. 计算 ZIP SHA-256；
2. 核对响应摘要；
3. 获取 `/v1/trust/keys`；
4. 验证 Ed25519 签名；
5. 通过本地 Skill 检查器重新扫描；
6. 显示权限和风险；
7. 用户确认后安装。

默认禁止安装未签名远程包，用户可以在 SkillHub 设置中显式调整。

## 6. 桌面功能

技能中心现在具有：

```text
推荐
SkillHub
我的安装
套件
```

### 推荐

服务器根据以下因素进行规则排序：

- 编辑精选；
- 项目和搜索需求；
- 已连接 Connector；
- 已安装 Skill；
- 下载热度；
- Connector 依赖缺失。

### SkillHub

支持搜索、查看发布者、版本、风险、下载量，并选择具体版本安装。

### Expert Registry

专家配置已接入 SkillHub 远程注册表：

- 个人专家默认以 `private` 保存，只有所有者和管理员可见；
- 组织专家和系统专家保存后进入待提交状态，审核通过后才会发布；
- 每次更新都生成不可变修订，客户端通过 `baseRevision` 做乐观并发控制；
- 桌面端优先保存到当前用户 Profile，再后台上传和拉取；
- 离线时继续使用本地缓存；恢复登录后自动同步；
- 多端同时编辑不会静默覆盖，桌面端会要求选择保留本地或采用远程版本；
- 组织和系统专家在桌面端只读，用户可复制为个人专家后定制。

专家注册表只同步专家定义、能力引用和运行策略，不上传项目资料、对话、成果物或 Connector 密钥。

管理后台提供独立的专家台账，管理员可以：

- 按生命周期、审核状态和可见范围筛选组织、系统和个人专家；
- 创建或编辑专家的职责、方法论、标准流程、输入输出和常用提示；
- 配置必需或推荐 Skill、工具服务，以及服务内具体工具范围；
- 管理权限、工作模式、模型和输入输出 Schema；
- 提交审核、通过并发布，或附带修改意见退回；
- 按全量、稳定比例或用户白名单分发组织和系统专家；
- 启用、停用或归档已通过审核的专家；
- 查看每次保存生成的不可变修订及修改人，并把历史内容恢复为新修订。

后台更新、审核、分发和回滚都使用 `baseRevision` 做乐观并发控制，避免覆盖桌面端或其他管理员刚保存的版本。回滚只恢复专家内容，当前负责人、可见范围和分发策略保持不变。组织或系统专家被停用、归档或移出当前用户的分发范围后，桌面端下次同步会移除对应的远程只读副本。

### 套件

管理员可创建 Collection，组合多个 Skill，并维护明确的展示顺序。内容运营后台同时支持精选位顺序、推荐规则和推荐结果模拟；推荐规则可按 Skill、分类、标签、任务关键词和 Connector 匹配，执行置顶、加减分或排除。

推荐接口会返回排序分数、推荐原因和命中的运营规则 ID，便于桌面端与管理后台解释结果。后续版本可将 Collection 扩展为同时包含 Expert、Connector、Template 和 TaskTemplate 的完整套件。

### 安装治理

管理后台按安装上报汇总活跃客户端、用户和项目范围、版本分布与待升级数量。待审核发布与安装台账放在同一个治理视图中，管理员可以直接批准或退回版本。

组织策略支持 `allowedSkillIds` 与 `defaultSkillIds` 联动。允许范围非空时，默认 Skill 必须位于允许范围内；角色或用户覆盖导致越界时，服务端会在最终策略中自动移除越界项。

### 发布草稿

具有 publisher/admin Token 时，可直接选择 Skill Creator 草稿，设置：

- private / organization / public；
- Changelog；
- 是否立即发布；
- 是否忽略非严重静态测试问题。

上传和发布仍由 SkillHub 权限与风险策略最终决定。

## 7. 当前边界

V1 尚未包含：

- PostgreSQL 和对象存储；
- OIDC/SSO；
- 异步恶意软件扫描；
- 多级审核、审核人分组和 SLA；
- 评分、评论和举报；
- 透明日志与密钥轮换；
- 增量更新；
- Connector 和完整 Suite 的远程发布；
- Expert 的多级审核、审核人分组和发布 SLA。

当前内网部署不依赖邮箱、公开注册或第三方身份服务。若未来接入统一身份平台，应保留现有稳定用户 ID 和 Skill 所有权关系。

这些能力应在真实内部试用数据和权限模型稳定后加入。
