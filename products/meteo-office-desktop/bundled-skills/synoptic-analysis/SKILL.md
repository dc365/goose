# 天气形势综合分析

## 前置校验

1. 明确资料来源、起报时间、有效时间、预报时效和区域。
2. 没有结构化气象资料时，列出缺口，不得虚构高低压、槽线、切变线或降水事实。
3. 区分实况、模式结果、诊断算法结果和人工推断。
4. 检查可用资料是否包含原始天气图，或是否已配置浏览器、气象数据、诊断、GIS 制图等图件能力。

## 分析流程

1. 地面：高低压、锋面、辐合与主要天气区。
2. 850hPa：低涡、切变、急流、水汽输送和暖湿区。
3. 500hPa：高空槽、脊、副热带高压与短波活动。
4. 200/300hPa：高空急流、辐散条件和系统配置。
5. 结合降水、对流和模式一致性分析未来演变。

## 图件工作流

1. 默认交付 1 至 4 张对结论有直接支撑作用的图件，不为凑数量重复展示相同信息：
   - 1 张综合形势主图；
   - 按需补充地面、850hPa、500hPa、200/300hPa 或降水风险图。
2. 分析网页天气图时，先用 `browser_snapshot` 核验来源、区域、层次、资料属性和时次，再用 `browser_take_screenshot` 获取图件。中央气象台高空实况图同时遵循 `nmc-upper-air-chart-analysis`，不得猜测网址或只凭 URL 判断产品。
3. 分析结构化格点或站点资料时，优先调用已配置的 GIS/气象制图工具生成 PNG；没有可用制图工具时使用资料中已有图件，不得用文字假装已经生成图片。
4. 图件应尽量裁剪到有效内容区域，保证标题、时次、图例和主要天气系统可辨。不得通过不安全代码、私自联网或 Shell 临时制图绕过当前权限。
5. 每张图件均登记为成果物，并记录：
   - 文件名或截图成果 URI；
   - 来源、时次、区域、层次和实况/预报属性；
   - `E1`、`E2` 等证据编号；
   - 该图直接支持的结论和不能支持的推断。
6. 用户明确要求带图但当前没有图件来源或图像工具时，将任务标记为部分完成，说明缺少的能力或资料；不得以纯文字结果声称已经完成带图交付。

## 输出结构

- 数据上下文
- 图件速览：按证据编号列出图片成果、图题和一句话判读
- 当前形势
- 系统配置
- 未来演变
- 风险区域
- 图件证据与不确定性

最终答案应在正文中引用图件编号，并在完成结果的 `artifacts` 中登记实际图片文件，推荐使用 `image/png`。截图或制图成果不存在时，不得填入虚假文件路径。

## 验证

- [ ] 每个事实均注明时次或 Evidence 引用
- [ ] 未把预报写成实况
- [ ] 结论与图件、诊断结果一致
- [ ] 图件来源、时次、层次、区域和资料属性完整
- [ ] 正文中的图件编号可以对应到实际图片成果
- [ ] 没有把单层图或低清截图能支持的结论范围夸大
