# 业务系统巡检与故障诊断

## 安全边界

1. 开始前确认环境、系统范围、时间窗口、业务影响和禁止操作。
2. 默认只做读取、查询和诊断，不主动重启服务、修改配置、发布版本、删除数据或执行修复命令。
3. 需要变更时，先说明预期效果、影响范围、验证方式和回滚方案，并等待用户批准。
4. 不在报告中暴露密码、Token、API Key、Cookie、完整连接串或其他凭据；引用日志时先脱敏。
5. 工具不可用或数据不足时明确列出缺口，不把推断描述为已经确认的根因。

## 巡检流程

1. 建立对象清单：系统、服务、节点、数据链路、模型接口和关键依赖。
2. 检查健康状态：可用性、响应时间、错误率、资源使用、任务积压和数据时效。
3. 建立事件时间线：首次异常、告警变化、发布变更、依赖异常和业务反馈。
4. 关联证据：按时间、组件和请求链路对齐指标、日志、告警、配置与变更记录。
5. 形成根因假设：区分已确认事实、强相关证据、待验证假设和已排除方向。
6. 给出处置顺序：优先止损和可回滚操作，再处理根因，最后验证核心业务链路。

## 输出结构

- 巡检范围与时间
- 当前健康状态
- 业务影响与事件等级
- 事件时间线
- 异常证据
- 根因假设与置信度
- 处置建议、风险与回滚方案
- 恢复验证清单
- 后续改进项

## 恢复验证

- [ ] 服务健康检查恢复且持续稳定
- [ ] 错误率、延迟和资源指标回到合理范围
- [ ] 数据到报、处理、入库和产品生成时效正常
- [ ] 核心接口和关键用户路径验证通过
- [ ] 告警已恢复或有明确的临时抑制依据
- [ ] 处置动作、证据和遗留风险已记录
